A Modal preemption of a simulation worker, segment worker or Stage 12 function is now recorded as an interrupted operation at WARNING instead of a failed one at ERROR, so it no longer opens telemetry error issues. Modal delivers a preemption as `KeyboardInterrupt` and runs the same input again; the executor, the gateway and the entrypoint now require policyengine-observability 3.0.7, which records an operation or request that ends in `KeyboardInterrupt` with the outcome `interrupted` at WARNING and leaves it out of `policyengine.error.count`. The request and operation count and duration metrics get `interrupted` as a new value of their `outcome` attribute. A span that ends in `KeyboardInterrupt` keeps an unset status, where it was set to error, and gets the attribute `policyengine.outcome` set to `interrupted`. A gateway or entrypoint request that ends in `KeyboardInterrupt`, which 3.0.4 recorded from its status code alone (as `success` at INFO when no status had been sent), is now recorded as `interrupted` at WARNING too.

The move from 3.0.4 also brings 3.0.5's change: a record written while a FastAPI endpoint runs, such as `exception.recorded`, carries the matched route template as `http.route` instead of `<unmatched>`.
