The gateway no longer records an exception, which `policyengine-observability` writes at ERROR severity, for a request it answers with a 400 or 404 client error: a `ValueError` from route resolution on `POST /simulate/economy/comparison` or `POST /simulate/economy/budget-window`, such as the unknown country sent by the authentication test that each deployment runs, an unknown job ID on `GET /jobs/{job_id}`, an unknown batch ID on `GET /budget-window-jobs/{batch_job_id}`, or an unknown kind on `GET /versions/{kind}`. Status codes and response bodies are unchanged, and each request's `request.completed` record still reports the response with outcome `client_error`. Server errors, and the 404 for a job whose gateway metadata exists but whose Modal call is missing or whose output has expired, still record their exceptions.

On both economy submission routes, a `ValueError` or `HuggingFaceDatasetReferenceError` without an SPM error code, raised while describing the route's bundle or resolving its SPM settings, now returns 500 instead of 400. Only bad data in the deployed bundle manifest can raise it. The gateway logs the exception with its traceback and records it as a handled server error, and the response has `status: "failed"` and the redacted error `Simulation failed (correlation_id=...)` instead of the exception text. A coded SPM error still returns 400 with structured `errors`. Both routes declare the 500 in the gateway's OpenAPI document and in the entrypoint's, so the generated client's two submission functions handle it as a declared status.
