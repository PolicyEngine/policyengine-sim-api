Added the `simulation` Postgres schema, in the database that holds the Public API's v2 tables, with its own Alembic migration chain at `migrations/` and the `policyengine-simulation-persistence` library. Each Simulation Entrypoint deploy now first runs the `migrate_simulation_database` job, which applies the chain's migrations on a deployment from `main` and only checks that the database is at the chain's head on a deployment from any other branch. The entrypoint gets `SIMULATION_DATABASE_URL` from Secret Manager, and `GET /ready` reports the schema's applied and expected revisions. No application data is stored in the schema yet.

Every deploy now needs the `SIMULATION_MIGRATION_DATABASE_URL` environment secret, the `SIMULATION_DATABASE_URL_SECRET_NAME` environment variable and the Secret Manager secret it names, in both `beta` and `prod`; without them the deploy stops at the migration job.
