The `x` and `y` fields of UK constituency and local-authority records, each area's integer position on the hex map, are now optional in the contract. A record validates without them, and its JSON leaves them out instead of writing `null`. Records from apps deployed for older policyengine.py versions, which still send both, validate and keep them. The gateway's OpenAPI document no longer lists them as required, and the contract now requires pydantic 2.12 or later, the first release with field-level `exclude_if`.

The executor no longer sends `x` or `y` on UK constituency and local-authority records. It no longer reads the `x` and `y` columns of policyengine.py's constituency lookup or attaches its packaged local-authority positions, and it no longer refuses a published area without a map position. Results from apps deployed from now on carry neither key, while apps deployed for older policyengine.py versions keep sending both. The beta integration check of a local-area breakdown now requires records without them.

The executor no longer ships `coordinates_lad22.csv` and `coordinates_lad23.csv`. Each boundary version's local-authority codes now come from `codes_lad22.csv` and `codes_lad23.csv`, which list exactly the codes the coordinate files did, so detecting LAD22 or LAD23 codes, and its checks, are unchanged. The Stage 12 static runtime file smoke test reports `lad22_codes` and `lad23_codes` instead of `lad22_coordinates` and `lad23_coordinates`.
