Added `POST /household-calculations` and `GET /household-calculations/{household_job_id}` to the Simulation Entrypoint. A submission names a household, and optionally a policy, stored in the Public API, with optional axes and SPM settings; the service reads them, creates a `household_jobs` row for the household's default year on the v2 version manifest's default worker, and starts its household function's call, answering 202 with the job's `job_id` and status, or 400, 422 or 503 with the reason. A read returns the job's status, result document and error message. A stored policy value with no end date applies to the end of 2200. Every deploy now gives the entrypoint the Modal token and the v2 manifest's Modal environment, and every staging deploy calculates the household that the `beta` variable `SIMULATION_STAGING_HOUSEHOLD_ID` names.
